# threaddemo

BORUIX 的**端到端多线程验收程序**：验证同一进程内派生多个线程时，地址空间、栈、错误码与线程局部
存储各自独立且正确。

[English](README.en.md)

## 测什么

程序在同一进程内派生两个线程，然后逐项验证：

| 验证项 | 内容 |
| --- | --- |
| **共享地址空间** | 两线程共享同一地址空间——对共享计数器的并发累加结果为预期值 |
| **独立栈** | 每个线程有自己的用户栈（各自 `mmap` 而来） |
| **汇合与退出码** | 主线程汇合两个线程，各自的退出码正确 |
| **每线程错误码** | 线程 A 设为"文件不存在"(2)，线程 B 设为"稍后重试"(11)；**跨让出反复读取**，各线程读到的必须始终是自己的值 |
| **线程局部存储** | 每线程从**自己的**存储区分配槽位并写入唯一标记；跨让出后标记必须保持。两线程的存储区与槽位指针**互不重叠** |
| **线程身份** | 线程 ID 各不相同，且进程 ID 相同 |

## 关键设计：错误码与局部存储如何做到"每线程一份"

每个线程安装自己的**线程控制块**，并让一个段基址寄存器指向它（内核在调度时负责保存与恢复该寄存
器）。错误码读写、以及线程局部存储的寻址，都经由这个寄存器，因此天然落到**当前线程自己的控制块**
上。

这带来一个直接的失败模式：**如果段基址在切换时泄漏**（即没有正确恢复），线程 B 就会读到线程 A 的
槽位。验收正是针对这一点——所以它要求跨让出反复读取，而不是读一次就算过。

## 用法

独立运行即可，无需参数。

```
threaddemo PASS (2 threads joined, per-thread errno + TLS + gettid/getpid identity)
```

## 退出码

| 退出码 | 含义 |
| --- | --- |
| `0` | 全部通过 |
| 非零 | 失败 |

## 构建

```bash
cargo build --release
```
